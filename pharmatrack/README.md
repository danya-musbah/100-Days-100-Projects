# PharmaTrack

**Drug Availability & Shortage Intelligence Platform for Libya**

## Problem Statement

In Libya, a person who needs a specific medicine often has to call or visit several pharmacies before finding it in stock. Pharmacies already run their own inventory systems, but these systems are typically old, isolated from one another, and provide no shared, public view of medicine availability. The result is wasted time, unnecessary travel, and no early warning when a medicine is becoming genuinely scarce across a region.

## Proposed Solution

PharmaTrack is **not** a replacement for pharmacy management software. It is a **data and intelligence layer** that sits on top of the systems pharmacies already use:

```
Legacy Pharmacy System
        ↓
   CSV Export
        ↓
   PharmaTrack
        ↓
Data Cleaning / Normalization
        ↓
   Central Dataset
        ↓
Search + Analytics + Prediction
```

Pharmacies export their inventory as CSV (a format virtually every system already supports), import it into PharmaTrack, and the platform cleans, normalizes, and matches that data against one shared medicine catalog. The public gets an honest, freshness-labeled availability search. Pharmacies get a dashboard. Administrators get system-wide analytics and shortage-risk signals.

## Features

- Public medicine search across brand name, generic name, active ingredient, strength, and dosage form
- Availability status (`AVAILABLE` / `LOW STOCK` / `OUT OF STOCK` / `UNKNOWN`) with an explicit **data-freshness system** (Fresh < 1h, Recent < 24h, Aging < 7d, Outdated > 7d) so stale data is never presented as current
- Pharmacy directory with an embedded OpenStreetMap view per pharmacy
- Pharmacy dashboard: KPIs, inventory trend chart, most-requested medicines, medicines at risk
- Full CSV import workflow: upload → detect columns → validate → normalize → medicine-match → duplicate-detect → confirm import
- Admin dashboard, pharmacy management (approve/activate/deactivate — demo only), medicine catalog browser, data-quality report, import history
- System-wide analytics: 8 charts covering availability over time, search demand, out-of-stock leaders, regional & category breakdowns, data freshness, and shortage trend
- Transparent, rule-based **shortage risk "Demo Prediction"** (clearly labeled as such — see Machine Learning Roadmap below)

## Data Pipeline (current prototype)

Implemented client-side in `js/import.js` and `js/matching.js`:

```
Raw CSV
   ↓
Validation        (missing name / quantity / date)
   ↓
Cleaning          (trim, case, whitespace)
   ↓
Normalization      (canonical column schema, ISO dates)
   ↓
Medicine Matching  (token-similarity fuzzy match against the catalog)
   ↓
Duplicate Detection
   ↓
Standardized Data → committed into the working inventory dataset
```

This is intentionally lightweight so a future Python service (Pandas for cleaning, RapidFuzz/TF-IDF/embeddings for matching) can replace it without changing how the UI calls it.

## Datasets

All files live in `/data` and are regenerated by the (not included in the deliverable, described here for transparency) synthetic-data generator used to build this prototype:

| File | Approx. rows | Notes |
|---|---|---|
| `pharmacies.csv` | 130 | Tripoli, Benghazi, Misrata, Zawiya, Zliten, Sabha + areas |
| `medicines.csv` | 520 | Brand/generic/ingredient/strength/form/category/manufacturer |
| `inventory.csv` | ~7,000 | Current snapshot per pharmacy × medicine carried |
| `inventory_history.csv` | ~21,500 | ~9 monthly snapshots per sampled pharmacy-medicine pair, with **declining**, **seasonal**, **stable**, and **volatile** patterns baked in |
| `medicine_searches.csv` | 13,000 | Public **search interest** (never described as confirmed demand or sales) |
| `sample_pharmacy_export_0{1,2,3}.csv` | ~15 each | Three different legacy column-naming conventions, with intentional messy rows (missing fields, invalid quantities, duplicates) to exercise the import pipeline |

Data is internally consistent: every inventory/history/search row references a real pharmacy and medicine ID, and quantities/statuses are derived consistently (`quantity ≥ 20 → AVAILABLE`, `1–19 → LOW_STOCK`, `0 → OUT_OF_STOCK`).
